## §1 · Project Identity

- **Title:** Jarvis Cinematic Animation Dependency Stack — `uv`-locked Python + `npm`-locked JavaScript
- **Scope:** Install, lock, and operationally verify all animation libraries identified in the preceding research (Three.js ecosystem, WebGL post-processing, particle VFX, SVG motion-path, audio-reactive, and browser-automation testing) across two package ecosystems: Python deps via `uv` + `uv.lock`; JavaScript/npm deps (which `uv` cannot manage) via `npm` + `package-lock.json` inside a Vite build project. Produce locked manifests, smoke-test proofs, and an end-to-end headless screenshot proving the WebGL bloom + god-rays pipeline is operational.
- **Target Platform:** macOS arm64 (Apple M-series), Python 3.12+, Node.js 20 LTS+, Chromium (headless via Playwright). Output HTML bundles served by the existing `http://localhost:8899` server.
- **Stack:**
  - Python: `uv` 0.6+ · Python 3.12 · `playwright` 1.50+ · `numpy` 2.4+ · `Pillow` 11+ · `pytest` 9+ · `ffmpeg-python` 0.2+
  - JavaScript: `npm` 10+ · `vite` 6+ · `three` r170+ · `postprocessing` 6.39+ · `ogl` 1.0+ · `gsap` 3.12+ · `animejs` 4+ · `meyda` 5+ · `@tsparticles/engine` 3.9+ · `tsparticles` 3.9+ · `pixi.js` 8+ · `motion` 10+ · `regl` 2.1+
  - System: `ffmpeg` 7+, `node` 20 LTS+, `uv` 0.6+
- **Mission:** Guarantee a fully reproducible, hermetically locked dual-ecosystem dependency stack that any agent can restore from lockfiles and that is provably capable of rendering Marvel-grade cinematic reactor animations.
- **Critical constraint note:** `uv` is a Python-only package manager and CANNOT install npm/JavaScript packages. The user's intent (lock everything, no drift) is honoured in full — via `uv.lock` for Python and `package-lock.json` for JavaScript. This is not a gap; it is the correct toolchain boundary.

## §4 · Constraints & Validation Gates

- **HC-1:** `uv` MUST manage ALL Python dependencies; no `pip install`, no `conda`, no system Python — any non-`uv` Python install is a FAIL
- **HC-2:** `npm` MUST manage ALL JavaScript dependencies; `uv` CANNOT install npm packages — any attempt to mix ecosystems at the package-install layer is a FAIL
- **HC-3:** Python 3.12+ is the minimum runtime; `uv python pin 3.12` enforces this in `.python-version`
- **HC-4:** Node.js 20 LTS+ is required; if `node --version` reports v18 or lower, HALT and instruct the user to upgrade via `brew install node@20`
- **HC-5:** `uv.lock` and `js/package-lock.json` MUST BOTH be committed; neither is gitignored
- **HC-6:** `uv sync --frozen` MUST succeed with zero resolution changes — the lock is authoritative
- **HC-7:** `npm ci` (not `npm install`) MUST be used for restoration; `npm install` updates the lockfile and is forbidden in the restore path
- **HC-8:** No LGPL-2.1 or incompatibly-licensed npm packages vendored from `Jarvis-Desktop` without an explicit license-compatibility review note
- **HC-9:** No global npm installs (`npm install -g ...`); all JS deps scoped to `js/node_modules`
- **HC-10:** Vite build output (`prototypes/dist/`) is gitignored; only source manifests and lockfiles are committed
- **C-1:** `js/vite.config.js` uses `build.rollupOptions.external: []` — all animation deps bundled into the output, not externally CDN-loaded
- **C-2:** Smoke tests are read-only and side-effect-free (no writes to prototype files, no server restarts)
- **C-3:** The headless Playwright test uses the `uv`-managed Playwright Python binding (not a separately installed Playwright npm package)
- **VG-1 (gates S-1; verifies HC-1, HC-2, HC-3, HC-4):** All four system version checks pass (`uv`, `python 3.12+`, `node 20+`, `ffmpeg 7+`); HALT with remediation instructions if any fails

## §7 · Quality Standards

- `pyproject.toml` uses `[project]` table with `requires-python = ">=3.12"` and pinned minimum versions for every dep
- `uv.lock` is committed, never gitignored; `uv sync --frozen` MUST succeed in CI
- `js/package.json` pins exact semver (`"three": "0.170.0"`, not `"^0.170.0"`) for all direct deps to prevent indirect drift
- `npm ci` (not `npm install`) used in all restore / CI paths
- Node ESM smoke scripts use `import` syntax (ESM only); no CommonJS `require()` in new code
- Vite config sets `build.target: 'esnext'` and `build.minify: true` for production bundles
- Playwright Python tests use the `uv`-managed playwright package; test assertions are fail-fast (first assertion failure aborts test, no silent swallow)
- All smoke scripts print explicit `OK` or `FAIL: <reason>` lines to stdout — no silent pass
- `docs/dependency-manifest.md` follows the repo's existing table formatting conventions; every row links to the library's GitHub or npm URL
- Lockfile hashes verified in T-16 before declaring any version of the stack stable
- `.gitignore` entry `prototypes/dist/` added so Vite build artifacts are not committed
- No `console.error` output during any smoke test run in headless Chrome
